# BMS 변환

코드: `Loaders/SxtgBmsConverter.cs`, `Loaders/BmsParser.cs`, `CustomTrackManager.LoadChartText`

커스텀 차트는 게임의 `SixtarGate.BMSConverter.Parse`(RVA `0x7EDB00`)에 BMS 텍스트로 넘깁니다. 게임 변환기는 게임 고유의 채널 배치를 기대하므로, sxtg2용 차트는 먼저 바꿔 줍니다.

## 게임 BMSConverter의 채널표

`BMSConverter.GetLaneIndex`(RVA `0x7ED300`) 기준 (10진 채널):

| 레인 (`LaneIndex`) | 일반 | 롱 |
| --- | --- | --- |
| LL | 11 | 51 |
| L | 12 | 52 |
| R | 18 | 58 |
| RR | 19 | 59 |
| Gate | 14 | 54 |
| LT | 13 | 53 |
| RT | 15 | 55 |
| GateAlarm (OPEN) | — | 56 → 레인 99 |

- 값 `00`, `0A`, `04`는 무시하고, 나머지 값은 전부 "마커"입니다.
- 롱노트는 같은 5x 채널의 연속 마커 두 개가 시작/끝 (채널별 buffer로 짝지음).
- 표에 없는 채널(예: 16)은 `KeyNotFoundException`.

## sxtg2 차트의 표현

sxtg2는 **레인을 채널로, 종류를 값으로** 씁니다 (`RhythmGame.LaneIndexOld` 순서).

| sxtg2 채널 | 레인 | → 게임 일반 채널 |
| --- | --- | --- |
| 16 | LL | 11 |
| 11 | L | 12 |
| 12 | R | 18 |
| 13 | RR | 19 |
| 14 | LT | 13 |
| 15 | RT | 15 |
| 18 | GATE | 14 |

| sxtg2 값 | 뜻 | → 게임 |
| --- | --- | --- |
| 01 | 일반 노트 | 같은 레인 일반 채널 |
| 02 / 03 | 롱 시작 / 끝 | 일반 채널 + 40 (5x) |
| 04 / 05 | OPEN 시작 / 끝 | 56 |

## 자동 판별 (`IsSxtgFormat`)

- 채널 19나 50~59가 하나라도 있으면 **게임 형식** → 그대로 씀
- 아니고 채널 16이 있거나, 11~18 채널에 값 02/03/05가 있으면 **sxtg2 형식** → 변환

## 변환 (`Convert`)

1. 노트 줄(`#mmmcc:data`)을 읽어 마커마다 (마디, 대상 채널) 그룹에 (위치, 해상도) 추가
2. 그룹마다 해상도를 최소공배수로 맞춰 한 줄로 다시 씀 (`01`이 마커)
3. 노트가 아닌 줄(`#BPM`, `#WAV` 등)은 그대로 둠

## 3자리 차트 (`NormalizeValueWidth`)

`#WAV` 키가 3글자(`#WAV001`)인 차트는 데이터 값도 3글자씩입니다(`001` 일반, `002`/`003` 롱, `010` BGM).
sxtg2는 앞의 `0`을 떼서 읽습니다(앞이 `0`이 아니면 무시). 모드도 변환 전에 2글자 값과 `#WAVxx`로 바꿔, 변환기와 게임이 같은 노트를 보게 합니다.

## 캐시

`LoadChartText`는 (경로, 파일 수정 시각)이 같으면 마지막 결과를 돌려줍니다. 플레이 진입 한 번에 `GotoPlayScene b__12`와 `MikazukiConverter.Parse` 두 곳에서 부르기 때문입니다.

## 곡 길이·BPM (`BmsParser`)

곡 목록에 쓸 값만 읽습니다.
- 기본 BPM: 첫 `#BPM 값` (없으면 150)
- 마지막 노트 끝 시각: (마디 + 위치/개수) × 240 / 기본 BPM, 롱노트는 끝 마커 시각. BPM 변경·마디 길이는 무시
- `album.Duration = 마지막 노트 끝 + 3초`

2026-10-30 정리 때 예전 구현과 실제 차트 15개 + 경계 사례 4개의 결과가 같음을 확인했습니다.
