## 1. 업데이트 내성: 실행 중 ICF 검사 (`Managers/IcfScanner.cs`, 새 파일)

**남아 있던 구멍(감사 2-1):** 런타임 가드는 1~3바이트 빈 스텁(`ret`, `xor al,al; ret` 등)만 잡았습니다. 업데이트로 훅 대상이
**내용 있는** 다른 함수와 접히면(실제 사례: `FinishProcessor.set_TrackEndTiming` ×11) 그대로 패치되어 엉뚱한 클래스의 `this`로
실행됩니다. 이걸 알려면 새 빌드로 Il2CppDumper를 다시 돌려 `icf_check.py`를 써야 했습니다.

**조치:**
- 부팅 때 IL2CPP 런타임의 모든 이미지 → 클래스 → 메서드를 훑어(`il2cpp_domain_get_assemblies` → `il2cpp_image_get_class` →
  `il2cpp_class_get_methods`, `Il2CppMethodInfo` 첫 필드 = `methodPointer`) 훅 대상 주소를 공유하는 메서드 수를 셉니다.
- 공유 개수가 허용치(기본 1)를 넘으면 그 패치 클래스를 건너뛰고 경고를 남깁니다. 필수 패치(`[CriticalPatch]`)면 `[Harmony] 필수 패치 빠짐` 오류도.
- 의도적으로 공유하는 대상은 `[IcfShared(n, "이유")]`로 표시: PlayLoading `b__2`/`b__4`(Outer Space 판 `DisplayClass35_0`과 공유, ×2).
- 결과는 `UserData/SixtarGateMod.IcfCounts.txt`(지문 = 빌드ID|`GameAssembly.dll` 크기|수정 시각, `LambdaTranslator`와 같음)에 저장해
  같은 빌드에서는 다시 훑지 않습니다. 훅 대상이 새로 생기면 다시 훑습니다. 검사가 실패하면 빈 스텁 검사만 하고 경고 한 줄.
- `NoteEffects`의 동적 훅(`NoteObject.set_HeadPosition`/`set_NoteLength`)도 부팅 검사에 넣고, 붙이기 직전에 `PatchResilience.IsSafeToPatchNow`로 확인합니다
  (작은 setter라 업데이트로 접히기 가장 쉬운 대상). 접혔으면 속도 카오스·히든·페이드를 끄고 경고.

## 3. 병목

- `FinishProcessor.UpdatePatternTime` Prefix는 **모든 곡**의 매 프레임에 불립니다. 공식 곡에서도 `TrackEndOffset`(IL2CPP 속성)을 먼저 읽던 것을,
  커스텀 곡이 아니면 그 전에 반환하게 바꿈.
- 깨진 자켓의 반복 동기 디코딩 제거(위 표).
- 부팅: ICF 검사 첫 실행 24~29ms, 이후 캐시. 람다 번역 3.3ms. 패치 단계 약 2.1초는 Harmony 디트로 생성 비용이라 이전과 같음(11-08 2.0초, 11-09 2.3초).

## 4. 확인하고 그대로 둔 것

- `CustomAudioManager`: 공식 곡 `Play`마다 `StopLocal` 호출은 사전 조회 한 번이라 비용 없음. 자연 종료된 스트림은 다음 `Stop`/`Play`에서 해제(누수 아님).
- `KeyViewer.TryBindLabels`의 `FindObjectOfType`은 플레이마다 바인딩될 때까지(최대 약 2초, 10프레임마다)만 실행.
- `PlayAssist` 점수 래퍼는 원본 델리게이트 포인터가 같으면 재사용(할당 없음).
- `OfflineBypass` 66개 훅: 구조 변화 없음. `UnitySessionModule.get_IsConnect` Prefix는 커넥터가 있으면 원본 실행.

## 5. 이번에 안 한 것

- **커스텀 곡 플레이는 이번에 실기로 돌리지 않았습니다.** 플레이 경로 변경은 null 검사·예외 대체·조기 반환 순서뿐(정상 경로의 동작은 같음)이고, 실기는 부팅~모드 선택까지 확인했습니다.
