## 1. 중국어(CJK) 메타데이터 로직 — `Loaders/TrackInfoParser.cs`, `Loaders/BmsParser.cs`

`04c94da`에서 중국어 간체·번체 키를 넣고 문서에 "완벽히 지원"이라고 적었으나, 중국어로 쓴 `info.txt`가 실제로 읽히는 조건이 좁습니다.

### 1-1. 전각 콜론 `：`을 구분자로 인식하지 않음 (코드, 영향 큼)
- `ParseTrackInfo`는 `line.IndexOf(':')`(반각 U+003A)만 찾고, 없으면 그 줄을 통째로 건너뜀(`TrackInfoParser.cs:60-61`).
- 중국어 IME로 입력하면 콜론은 보통 전각 `：`(U+FF1A)라 `曲名：xxx` 줄이 모두 무시됨 → 제목·아티스트·난이도가 비고, 제목은 BMS `#TITLE`(sxtg2 차트는 대개 `test`) 또는 폴더 이름이 됨.
- 즉 지금 중국어 키 지원은 사용자가 콜론을 반각으로 쳤을 때만 동작함.
- 고칠 방향: `:`와 `：` 중 먼저 나오는 쪽을 구분자로 사용.

### 1-2. 난이도 구분자·숫자가 반각만 됨 (코드)
- 난이도 값은 `','`, `' '`, `'\t'`로만 나눔(`:71`). 중국어 입력의 전각 쉼표 `，`(U+FF0C), 모점 `、`(U+3001), 슬래시 `/`로 쓴 `10，10，10，10`은 한 덩어리 → `int.TryParse` 실패 → 난이도가 빈 목록 → 템플릿 곡 난이도로 대체.
- 전각 숫자 `１０`도 `int.TryParse`가 읽지 못함(.NET 기본 숫자 파싱은 ASCII 숫자만 받음).
- 고칠 방향: 분리 문자에 `，、/；` 추가, 파싱 전 전각 숫자(U+FF10~FF19)를 반각으로 바꿈.

### 1-3. 키를 `Contains`로 맞춰 다른 항목이 제목·아티스트를 덮어씀 (코드)
같은 키가 여러 번 나오면 나중 값이 이기는데, 부분 일치라 다른 뜻의 키도 걸림:

| 키 예 | 걸리는 조건 | 결과 |
| --- | --- | --- |
| `副标题`, `副標題`, `subtitle` | `Contains("标题")`/`("標題")`/`("title")` | 부제가 제목을 덮음 |
| `谱面作者`, `譜面作者` | `Contains("作者")` | 채보자가 아티스트를 덮음 |
| `chart artist`, `채보 아티스트` | `Contains("artist")`/`("아티스트")` | 같음 |
| `作词`(작사) | 걸리지 않음 | 무시(정상) |

- 고칠 방향: 키 첫 일치만 채택(먼저 나온 값 유지) + `副`/`sub`/`谱`/`譜`/`chart`/`채보` 포함 키 제외. 또는 정확 일치 목록으로 바꿈.

### 1-4. 문자 인코딩은 UTF-8 고정 (코드)
- `File.ReadLines`/`File.ReadAllLines`(인코딩 미지정) = UTF-8. 중국 Windows 메모장의 옛 기본값 ANSI(GBK), 대만 Big5, 한국 CP949로 저장한 `info.txt`는 글자가 깨짐(U+FFFD). 사용자 곡 15개는 모두 UTF-8이라 지금은 문제없음(실측: `il vento d'oro/info.txt` 바이트가 UTF-8).
- BMS는 전통적으로 Shift-JIS가 많음. `info.txt`가 없는 일본 BMS는 `#TITLE`이 깨진 채로 폴더 이름 대신 표시됨.
- 고칠 방향: UTF-8로 엄격 디코딩(`throwOnInvalidBytes`)에 실패하면 `CodePagesEncodingProvider`로 GBK(936)/Shift-JIS(932)/CP949 시도, 또는 BMS 제목에 U+FFFD가 있으면 폴더 이름 유지.

### 1-5. 게임 글꼴에 간체 글자가 없을 수 있음 (추정)
- 게임 언어는 `ELanguage { KR, JP, EN }` 셋뿐(`il2cpp_dump/dump.cs`). 일본어 글꼴에는 간체 전용 자형(`标`, `艺`, `师`, `难`, `级` 등)이 없는 경우가 많아 간체 제목이 □로 보일 수 있음. 실기 미확인. 번체·일본어 공통 한자는 대부분 나옴(실측: 일본어 곡 4개 정상 표시).

### 1-6. 축약형 교정 정규식 오탐 (실측)
`NormalizeMetadataText`와 같은 정규식을 PowerShell(.NET 정규식)로 돌린 결과:

| 입력 | 결과 | 원인 |
| --- | --- | --- |
| `Guns N' Roses` | `Guns N'Roses` ✗ | `RegexPrefix`가 `N`을 프랑스어식 접두사(`n'`)로 봄 |
| `Mister 'T'` | `Mister'T'` ✗ | `RegexContractions`가 `'T`를 `'t`(축약)로 봄(대소문자 무시) |
| `the 'S' Club` | `the'S'Club` ✗ | 접두사·축약 두 규칙이 겹침 |
| `rock '  n '  roll` | `rock 'n' roll` ✓ | |
| `you'  re`, `D ' Arc` | `you're`, `D'Arc` ✓ | |
| `Livin' On A Prayer`, `Rockin' 'Til Dawn`, `L'Arc~en~Ciel` | 그대로 ✓ | |
| `中文 Title` | 그대로 ✓ | CJK 글자 사이엔 `\b`가 없어 영향 없음 |

- 문서에 적혀 있던 "왼쪽 작은따옴표 `‘`(U+2018) 처리"는 사실이 아님: 문자 집합은 `'’`＇′`뿐. 또 따옴표는 축약 패턴에 걸릴 때만 `'`로 바뀌고, 그 밖의 `’`는 그대로 남음.
- 고칠 방향: `RegexPrefix`를 소문자 단일 글자(`[cdjlmnst]`) + 대소문자 구분으로 좁히고, `RegexContractions`도 대소문자 구분(축약 꼬리는 소문자)으로.

### 1-7. 그 밖
- 트랙 ID = `"CUSTOM_" + 폴더 이름 대문자 + 공백→_`. CJK 폴더 이름도 문제없이 쓰임(실측: `どりーむもーど` 플레이·결과 화면, 2026-11-07). 다만 `A B`와 `A_B` 폴더는 같은 ID가 되어 사전에는 나중 폴더만 남음(코드, `CustomTrackManager.cs:85`).
- 일본어 키(`タイトル`, `アーティスト`, `難易度`)는 지원하지 않음. `曲名`/`難度`는 중국어 키로 우연히 겹쳐 동작.
- `FindTrackInfoFile`은 정해진 이름이 없으면 **첫 `.txt`**를 읽음. 가사·설명 파일(`说明.txt`, `lyrics.txt`)이 그 자리에 오면 거기서 `title`류 줄을 집을 수 있음.

## 2. 업데이트 내성 — `Managers/PatchResilience.cs`, `LambdaTranslator.cs`, `UpdateGuard.cs`, `tools/version_diff/`

잘 되어 있는 것: 클로저·코루틴 이름 비의존, 오타 이름 양방향, 자명 스텁(1~3바이트) ICF 자동 스킵, 패치 클래스별 try/catch(한 패치 실패가 나머지를 막지 않음), 빌드 경고, Unity 예외 전달, 업데이트 비교 스크립트.

남은 구멍(모두 코드 확인):

1. **비자명 ICF는 실행 시 못 잡음.** 런타임 가드는 `ret`/`ret 0`/`xor al,al;ret`/`xor eax,eax;ret`/`mov al,1;ret`만 봄. 업데이트로 패치 대상이 내용 있는 다른 함수와 접히면(`set_TrackEndTiming`×11, `NoteJudgedObserver.Notify` 같은 경우) 그대로 패치되어 엉뚱한 `this`로 실행됨. 같은 주소를 모드 패치끼리 공유하는 경우도 `DebugLog`(기본 꺼짐)로만 알림.
   - `check_update.ps1`도 ICF 개수는 보지 않음. 지금은 새 빌드로 Il2CppDumper `script.json`을 다시 만들어 `Address` 중복을 손으로 세야 함.
   - 고칠 방향: `HOOK_TABLE.md`의 대상별 RVA·ICF 수를 스크립트가 새 `script.json`과 대조하도록 추가.
2. **`ShouldSkipForIcfStub`은 대상 중 하나만 스텁이어도 패치 클래스 전체를 건너뜀.** `TargetMethods`로 여러 대상을 묶은 클래스는 정상 대상까지 빠짐.
3. **필수 패치 실패가 일반 실패와 같은 무게.** `BackEndWebRequest.InitializeModule` 같은 부팅 우회가 실패하면 오프라인에서 `WaitUntil(() => Web.HasInitialized)`에 영구 정지하는데, 로그는 `[Harmony] … N개 실패` 한 줄. 어떤 패치가 "없으면 부팅 안 됨"인지 표시가 없음.
4. **빌드 판별이 `.acf`의 `buildid`에만 의존.** DepotDownloader로 받은 설치나 `.acf`를 고쳐 업데이트를 막은 경우 실제 바이너리와 표시가 다를 수 있음. `LambdaTranslator`는 이미 `GameAssembly.dll` 크기·시각을 지문으로 쓰므로, `UpdateGuard`도 검증된 빌드별 `GameAssembly.dll` 크기(또는 해시)를 함께 대조하면 됨.
5. **람다 본문 스캔이 `REX.W`(0x48/0x4C)만 봄.** 기준 레지스터가 r8~r15인 `mov`(REX.B: 0x49/0x4D)나 disp32(필드 오프셋 > 0x7F)는 못 읽고, 그때 **경고 없이** `matchIndex` 순서로 고름(AGENTS.md 4-15 "한계"에 적힌 것과 같은 결론, 원인을 구체화). 고칠 방향: 스캔 실패 시 `Warning` 한 줄.
6. **`VerifiedBuilds`가 코드 상수.** 새 빌드를 검증하면 모드를 다시 빌드해야 경고가 사라짐. 의도된 설계(검증 기록을 코드와 함께 남김)라 문서에만 적어 둠.
