# 코드 점검 2026-11-22 (v2.3.1)

이전 점검(`REVIEW_2026-11-19.md`) 이후 남은 항목을 코드에서 다시 확인하고 정리한 기록입니다. 게임 실기는 돌리지 않았고, 빌드·단위 테스트·오프라인 도구로만 확인했습니다.

## 1. 빈 `catch` 12곳 정리

전에는 예외를 삼키고 아무 기록도 남기지 않는 `catch { }`가 12곳이었습니다. 업데이트로 무엇이 깨졌는지 추적하기 어려운 구멍이라 아래 세 방식 중 하나로 바꿨습니다.

| 방식 | 곳 | 이유 |
| --- | --- | --- |
| 로그를 남김 | `CustomMarathon.Update`(Esc 입력 읽기 실패, 한 번만 경고), `PatchPreflight`(예상 밖 예외), `PatchResilience.CreatePropertyCloner`(속성 복제 실패), `UpdateGuard`(메타데이터 위치 검색), `NoteEffects`(동적 패치 해제 2곳) | 원인 추적에 필요한 값이 있음 (`Core.DebugLog`, `DebugLog=1`일 때만 출력) |
| 예외 필터로 좁힘 | `CustomNoteSkin.DecodeAll`(`IOException`/`UnauthorizedAccessException`), `TextDecoder`(`DecoderFallbackException`/`ArgumentException`/`NotSupportedException`) | 예상한 실패만 삼키고 나머지는 그대로 올라감 |
| 이유 주석을 붙임 | `CustomAudioManager.PlayLocal`의 정리 호출, `NoteEffects`의 파괴된 `CanvasGroup`, `TextDecoder`의 문화권·코드 페이지 등록 | 정리 중 실패이거나 실패해도 다음 단계가 처리함 |

**작업 스레드 주의:** `CustomNoteSkin.DecodeAll`은 `ModLog.RunCaptured` 밖의 작업 스레드라 `MelonLogger`를 직접 부를 수 없습니다. 실패는 `Rgba == null`로 알리고, 메인 스레드가 `LoadImage`로 다시 시도하면서 거기서 보고합니다.

## 2. `PngDecoder` 픽셀 상한

- 문제: 헤더가 16384×16384까지 허용돼, 큰 PNG 한 장이 해독 버퍼(`raw` 약 1GB + `pixels` 약 1GB)를 작업 스레드에서 잡다가 메모리 부족을 낼 수 있었습니다.
- 수정: `PngDecoder.MaxPixels = 40,000,000`(약 6300×6300). 넘으면 `false`를 돌려 호출자(`MediaOverrideManager`, `CustomNoteSkin`)가 Unity `LoadImage` 폴백으로 갑니다.
- 일반 자켓(1080p~4K)은 영향 없음.

## 4. 이번에 읽고 문제 없다고 본 것

- `UpdateGuard`(지문 비교·실기 확인 기록·Unity 로그 전달): 스레드 접근(`Interlocked`/`Volatile`)과 상한 처리가 맞음.
- `CustomMarathon`: 씬 흐름(`PlayLoading → Renewal_Play → Loading → Result`)과 큐 정리가 맞음. Esc 입력 오류 처리만 위 1번에서 보강.
