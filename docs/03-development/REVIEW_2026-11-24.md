# 코드 점검 2026-11-24 (v2.3.4)

2026-11-23 점검(v2.3.2·v2.3.3)에서 보지 않은 곡 목록·미디어 쪽(`CustomTrackManager`, `MediaOverrideManager`, `CustomJackets`, `CustomMarathon`, `TrackInfoParser`, `CustomAlbumInfo`)을 중심으로 다시 훑었습니다.

## 1. 병목: `hwa\` 변경 시 모든 곡을 메인 스레드에서 다시 해석

`CustomTrackManager.RefreshIfChanged`는 CUSTOM 탭에 들어갈 때(`GetTracks("CUSTOM")` Prefix, 메인 스레드) `hwa\` 지문이 바뀌었으면 `ScanHwaFolder`를 통째로 다시 돌렸습니다. 곡 하나를 추가하거나 `info.txt` 한 줄만 고쳐도 모든 곡의 `info.txt`·BMS(`BmsParser.ParseBmsFile`, 차트 전체 해석)를 다시 읽어, 15곡 기준 부팅 때 작업 스레드에서 0.1~0.4초 걸리던 일이 탭 전환 순간 메인 스레드에서 일어났습니다.

| 전 | 후 |
| --- | --- |
| 폴더마다 `Directory.GetFiles`(이름만) → 매번 `BuildAlbumInfo` | 폴더마다 `DirectoryInfo.GetFiles` 한 번(이름·크기·수정 시각) → 폴더 지문(`FoldFiles`, 변경 감지와 같은 함수)이 지난 스캔과 같으면 앨범 객체를 그대로 재사용 |
| — | 재사용 캐시 `_folderCache`: 폴더 경로 → (지문, 충돌 번호 전 곡 ID, 앨범). 스캔마다 이번에 본 폴더로만 새로 만들어 지운 폴더는 빠짐 |
| 곡 ID 충돌 번호(`_2`)는 스캔 순서대로 | 재사용 앨범도 기본 ID로 되돌린 뒤 같은 규칙으로 다시 붙임(폴더를 지우면 번호가 당겨지는 동작 동일) |
| 로그 `다시 스캔 (N곡)` | `다시 스캔 (N곡, 바뀌지 않은 폴더 M곡은 다시 읽지 않음)` |

폴더 읽기 실패는 전에는 빈 목록으로 조용히 넘겼는데, 이제 `IOException`/`UnauthorizedAccessException`만 잡고 `[CustomTrackManager] 폴더 읽기 실패` 경고를 남깁니다.

## 2. 알려진 한계 해소: 자켓 그림을 바꿔도 게임을 다시 켜야 반영

`MediaOverrideManager`의 스프라이트 캐시·대기·실패 기록이 **곡 ID**만 키로 써서, `hwa\` 재스캔으로 `JacketPath`가 바뀌어도 옛 스프라이트가 계속 나왔습니다(`CURRENT_STATUS.md` 알려진 한계).

- `CustomAlbumInfo.JacketStamp`(자켓 파일 크기:수정 시각 틱)를 스캔 때 열거 결과에서 채움(추가 stat 없음).
- 캐시 키 = 곡 ID + `|` + `JacketStamp`. 그림을 바꾸면(같은 파일명이어도) 다음 CUSTOM 탭 진입의 재스캔 뒤 키가 달라져 새로 해독.
- 같은 곡의 옛 키 항목은 새 스프라이트를 넣을 때 캐시에서 뺌(`CurrentKeyByTrack`). 화면의 이미지가 아직 옛 스프라이트를 쓸 수 있어 **파괴하지 않음** — 자켓을 바꿀 때마다 옛 텍스처 하나가 남는 것은 의도(게임을 끄면 해제).
- 실패 기록도 같은 키라, 깨진 그림을 고쳐 저장하면 재스캔 뒤 다시 시도(전에는 `ClearFailed`가 전부 지워서 같은 결과).

## 3. 병목: 자켓 캐시 조회의 Unity null 비교

`GetOrCreateAlbumSprite`/`RequestAlbumSprite`가 캐시 적중마다 `cached != null`(IL2CPP `op_Equality`)을 불렀습니다. 곡 목록을 스크롤하면 커스텀 곡 행마다 두 번(`SetTrack` + 번들 콜백) 불리는 경로입니다. 캐시 스프라이트는 `DontUnloadUnusedAsset`이고 이 모드가 파괴하지 않으므로 관리 비교(`is not null`)로 바꿨습니다.

## 4. 감사했지만 고치지 않은 것

- `TrackInfoParser.ParseLines`의 LINQ(`Any`, `Select`): 스캔 때만, 이제는 바뀐 폴더만 돌아서 둠.
- `RandomNoteSkin`의 `GetComponentsInChildren(...).ToArray()`: 플레이당 프리팹 1회.
- `CustomMarathon`: 마라톤 중 `hwa\`가 재스캔되면 대기열의 `ITrack`은 옛 목록 객체지만 곡 ID로 앨범을 찾으므로 그대로 동작. 지운 곡이 대기열에 남으면 `GotoPlayScene`이 기본 1노트 곡으로 처리(전과 같음).
- `LoadChartText`: 같은 경로·같은 수정 시각이면 변환 결과 재사용(이미 있음).

## 5. 검증

- Release/Debug 빌드 경고·오류 0, xUnit 77건 통과, `tools/bodycheck` 통과, `tools/sigcheck` 통과 114·오류 0·경고 0·대체 해석 0, `tools/lambdascan` `ALL PASS`.
- `CustomTrackManager`·`MediaOverrideManager`는 IL2CPP/Unity 형식을 써서 단위 테스트 대상이 아님. **실기 미실행** — 다음에 게임을 켤 때 확인할 것:
  1. 시작 로그 `검색 완료: 커스텀 곡 N곡 발견`(첫 스캔은 재사용 없음).
  2. 게임을 켠 채 `hwa\`에 곡 하나를 추가 → 다른 탭에서 CUSTOM 탭으로 → `다시 스캔 (N+1곡, 바뀌지 않은 폴더 N곡은 다시 읽지 않음)`.
  3. 한 곡의 `thumbnail.png`를 다른 그림으로 덮어쓰기 → CUSTOM 탭 재진입 → 그 곡을 고르면 새 자켓.
  4. 커스텀 곡 1곡 결과 화면까지.

## 6. 2차 전 파일 심층 감사 (v2.3.5)

저장소 전체(`Core.cs`, `Features/` 14개, `Managers/` 15개, `Loaders/` 5개, `tools/`, `tests/`, `docs/`)를 4개 영역으로 나누어 전수 감사하고, 확인된 업데이트 내성 빈틈·성능 병목·런타임 버그·문서 불일치를 일괄 정리했습니다.

### 업데이트 내성 강화
- **`CustomAudioManager` 오타 내성 완성:** `SetCurrectionVolume` 훅은 `"CurrectionVolume"`/`"CorrectionVolume"`을 동적 해석하면서 `PlayLocal`/`ApplyVolumes`는 컴파일 타임 속성 `module.CurrectionVolume`을 직접 참조해 오타 수정 시 `PatchPreflight`가 커스텀 오디오 훅 전체를 탈락시킬 수 있었음 → `PatchResilience.CreateValueGetter<float>`로 통일.
- **`UpdateGuard` 2번째 부팅 검증 우회 수정:** `VerifiedBuilds` 빌드에서 `global-metadata.dat`·`UnityPlayer.dll`·`loaderVersion`이 바뀌어도 1번째 부팅에서 `BuildState.txt`를 즉시 덮어써 2번째 부팅부터 실기 플레이 없이 "검증된 빌드"로 통과하던 문제 → `ListVerified && _fingerprintChanged`일 때는 실기 플레이 통과 전까지 덮어쓰지 않음. `fallbackResolved > 0`일 때도 실기 확인 기록 차단.
- **`PatchPreflight` 닫힌 제네릭 사전 JIT 복구:** 닫힌 제네릭 메서드를 무조건 `GetGenericMethodDefinition()`으로 바꿔 `PrepareMethod`가 건너뛰어지던 문제 → `ContainsGenericParameters`가 참일 때만 정의로 변환.
- **`PatchSignatureCheck` + `NoteEffects` 보강:** `ref object` vs 값 형식 차단, `bool`↔`byte`·`char`↔`short` 동일 크기 정수 오판 제거, `___field` 주입 필드 존재·형식 검사 추가. `NoteEffects.SetNotePatches()`에도 `PatchSignatureCheck` 적용.
- **`IcfScanner` 미발견 주소 `-1` 구분:** `il2cpp_image_get_class` 순회에 나오지 않는 닫힌 제네릭 클래스 메서드가 `Count = 0`(안전)으로 캐시되던 문제 → `-1`(미발견 경고)로 기록.
- **`X64Decoder` / `LambdaTranslator`:** `vzeroupper`/`vzeroall` ModRM 없음 처리, SIB 인덱스 레지스터(`index != 4`) 시 `BaseReg = -1`, `0x3C`(`cmp al, imm8`) `RAX` clobber 제거, `ScanNative`에 `VirtualQuery` 페이지 경계 제한 추가.
- **`PatchResilience.LogResolveWarning`:** 오프라인 `tools/sigcheck`에서 MelonLoader 부재 예외로 대체 해석 경고가 "대상 미확인"으로 묻히지 않도록 방어.

### 병목 해결 및 버그·누수 수정
- **`PngDecoder`:** RGBA(`colorType == 6`) 출력을 픽셀당 `Buffer.BlockCopy`에서 행 단위 1회로(1080p당 207만 회 → 1,080회), `filter == 0` 스킵 + 루프 외부화. 손상된 zlib(`IDAT`)에서 `InvalidDataException` 대신 `false` 반환, `IHDR` compression/filter 0 검증.
- **`CustomTrackManager`:** `ScanHwaFolder` 단일 순회에서 `_lastHwaStamp`를 함께 계산(부팅 2회·갱신 3회 → 1회 열거).
- **`MediaOverrideManager`:** 비동기/동기 자켓 로드 경쟁 시 중복 GPU 텍스처 누수 방지, `MakeSprite` 예외 시 `Texture2D` 파괴, JPG/비-PNG 자켓의 작업 스레드 `byte[]` 재사용으로 메인 스레드 이중 `File.ReadAllBytes` 제거.
- **`Overlay` / `Core` / `CustomBga` / `RandomNoteSkin` / `PlayAssist` / `CustomJackets` / `CustomMarathon` / `KeyViewer`:** `HideAll()` 파괴 캔버스 가드, `Label()` 외곽선 알파 갱신, `CustomMarathon.Update`를 `Overlay.Begin()` 이전으로 분리, `CustomBga` `_playSeq` 세대 카운터, `RandomNoteSkin` `EnsureCatalog` null 재시도·`ImagesOf` LINQ/Unity null 제거, `PlayAssist.OnTickEvent` `Finalizer` 전환, `CustomJackets` `TrackID` 1회 조회·무자켓 코루틴 생략, `AtomicFile` 실패 시 `.tmp` 정리.
- **`BmsParser` / `SxtgBmsConverter` / `TrackInfoParser`:** `#TITLE`/`#ARTIST` 공백 구분자, `Infinity` 차단, 게임 네이티브 채널(`19`, `51`~`59`, 일반 WAV 키) `MaxTime` 반영, `IsSxtgFormat` `'04'` 추가, `BGA作者`/`Jacket` 크레딧 필터링 및 0 이하 난이도 제외.
- **도구:** `tools/release.ps1`·`tools/version_diff/check_update.ps1` PowerShell 5.1 stderr 안전 처리, `tools/sigcheck` `Directory.Build.props.user` 연동 및 `SameNameMethods` 중복 제거.
