## 3. 실기 확인 자동 기록

- 흐름(11-16 실기 로그로 확인): `PlayLoading` → `Renewal_Play` → `Loading` → `Result`. 중간에 그만두면 `Renewal_Play` → `Loading` → `MusicSelect`.
- `Core.OnSceneWasLoaded` → `UpdateGuard.OnSceneLoaded(씬, IsCustomTrackActive, 앨범 제목)`:
  - `Renewal_Play` + 커스텀 곡: 그때의 예외 개수를 기억.
  - `Loading`: 무시.
  - `Result` + 커스텀 곡 + 그 사이 예외 0건 + 이번 실행에 지문이 저장됨(패치 전부 적용) → `verifiedPlay=yyyy-MM-dd HH:mm 곡 제목`을 지문 파일에 씀. 예외가 있었으면 경고만.
  - 그 밖의 씬: 진행 중인 플레이를 버림.
  - 이미 검증 목록에 있고 지문 그대로인 빌드, 이번 실행에 이미 기록한 경우는 다시 쓰지 않음.
- 다음 부팅: 지문이 **모든 키에서 그대로**(`BuildFingerprint.SameBuild`, 빠진 키나 `GameAssembly`/메타데이터 헤더를 못 읽은 경우는 아님)일 때만 기록을 이어받아 `[UpdateGuard] 게임 빌드 … 이 PC에서 실기 플레이로 확인된 지문`, 결과 줄 `정상 (이 PC에서 실기 플레이로 확인된 빌드: …)`. 지문이 바뀌면 다음 저장에서 기록이 빠짐.
- 개발 중이면 기록을 본 뒤 `UpdateGuard.VerifiedBuilds`/`VerifiedGameAssemblySizes`와 AGENTS.md에도 적을 것(다른 PC·새 설치는 기록이 없으므로).
- **판정 한계:** "결과 화면까지, 게임 내부 예외 0"은 곡이 끝까지 돌았다는 뜻이지 모든 기능(자켓·BGA·판정 보조)이 맞게 보였다는 뜻은 아님. 화면 확인은 여전히 사람 몫.
