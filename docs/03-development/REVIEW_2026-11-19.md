# 코드 리뷰 2026-11-19: 패치 인자 시그니처 대조

게임 빌드 `26455233`(ver 1.1.007) 기준. 실기는 실행하지 않았고, 오프라인 검증만 했습니다(아래 "검증").

## 1. 찾은 빈틈

업데이트 내성 계층은 다음 경우를 이미 막고 있었습니다.

| 업데이트로 생기는 일 | 막는 곳 |
| --- | --- |
| 모드가 쓰는 인터롭 멤버가 사라짐 | `PatchPreflight` (사전 JIT·토큰 검사) |
| 훅 대상이 다른 함수와 주소를 공유하게 됨 (ICF) | `IcfScanner` + 빈 스텁 검사 |
| 클로저·코루틴 번호가 밀림 | `LambdaTranslator` |
| 게임 오타가 고쳐짐 | `ResolveMethod` 후보 이름 |
| 게임 파일이 바뀜 | `UpdateGuard` 지문 |

비어 있던 경우는 **훅 대상 인자의 형식이 바뀌는 것**입니다. Harmony는 Prefix/Postfix 인자를 이름으로만 대상 인자에 묶고 형식은 확인하지 않습니다. 모드는 옛 인터롭으로 컴파일됐으니 컴파일 오류도 나지 않고, 패치는 그대로 붙습니다. 그러면 첫 호출에서 크기가 다른 값을 읽어 쓰레기 값, 스택 손상, 네이티브 크래시가 납니다. 예를 들어 `int lane`이 `long lane`이 되거나, 콜백이 `Action<int>`에서 `Action<long>`으로 바뀌는 경우입니다. AGENTS.md의 "매 노트 훅 실험 시 원인 미확인 네이티브 크래시"와 같은 종류의 증상이 업데이트 뒤에 조용히 생길 수 있는 경로였습니다.

관련된 빈틈이 하나 더 있었습니다. `PatchResilience.ResolveMethod`는 인자 형식 없이 이름으로만 찾을 때 HarmonyX `AccessTools.Method`를 씁니다. 업데이트로 같은 이름의 오버로드가 생기면 이 메서드가 `AmbiguousMatchException`을 던져 `TargetMethod` 전체가 실패했습니다. 또 이름과 인자 개수로 대체해 찾는 경로는 로그 없이 조용히 대체했습니다.

## 2. 변경

1. **`Managers/PatchSignatureCheck.cs` (신규, 순수 리플렉션):** 패치 클래스의 Prefix/Postfix/Finalizer 인자를 해석된 모든 대상과 대조합니다.
   - 건너뜀: 대상에 없는 인자 이름, 값 형식 불일치(같은 크기의 정수·열거형·`bool`끼리는 허용), 정적 대상의 `__instance`, void 대상의 `__result`.
   - 경고만: 참조 형식이 서로 대입 불가. 인터롭 래퍼는 포인터만 감싸므로 즉시 크래시는 아닙니다.
   - 무시: `__state`·`__exception`·`__originalMethod`·`__runOriginal`·`__args`·`___필드`·`__0` 같은 특수 인자, `object`로 받는 인자.
2. **`PatchResilience.ApplyAllPatches`:** 대상을 해석한 직후, ICF 스캔 전에 대조합니다. 불일치하면 `[Harmony/Signature] '…' 건너뜀: …`을 남기고 사전 검사 개수에 합산합니다. `[CriticalPatch]`면 필수 빠짐에도 올라가 `업데이트 점검 결과: 문제 있음`이 됩니다. 대조 중 예외가 나면 건너뛰지 않고 경고만 남깁니다(대조기 버그로 멀쩡한 패치를 잃지 않게).
3. **`PatchResilience.ResolveMethod`:** `AmbiguousMatchException`을 잡아 이름·개수 대조로 넘깁니다. 후보가 여럿이면 고르지 않고 `[Harmony/Resolve]` 경고를 남깁니다. 이름·개수로 대체해 찾은 경우에도 경고합니다(같은 문장은 한 번만). 속성 기반 `[HarmonyPatch]`에서 같은 예외가 나면 "인자 형식을 지정해야 함"이라는 힌트를 붙입니다.
4. **`tools/sigcheck` (신규):** 빌드된 모드 DLL을 불러 모드 안의 `PatchSignatureCheck`를 그대로 실행합니다. 대상은 게임 `Il2CppAssemblies`의 시그니처입니다. 업데이트 뒤 MelonLoader가 인터롭을 새로 만들었으면, 모드를 실행하기 전에 판정을 미리 볼 수 있습니다. 종료 코드는 0(통과), 1(건너뛰어질 패치 있음), 2(실행 실패)입니다. `check_update.ps1`의 5단계로 연결했습니다.
5. **테스트:** `PatchSignatureCheckTests.cs` 10건을 추가해 총 50건입니다.

## 4. 점검했지만 고치지 않은 것

- 플레이마다 쌓이는 정적 컬렉션(`RandomNoteSkin.InstanceParts`, `CustomNoteSkin.Skinned`, `NoteEffects.*`, `JudgmentBar.HitHistory`, `CustomJackets._rowTrackIds`): 모두 플레이 준비나 씬 경계에서 비워집니다. 누수가 없습니다.
- 참조 형식 불일치를 건너뜀으로 올릴지 검토했습니다. 인터롭 형식 계층(인터페이스 래퍼, `Il2CppObjectBase`로 받는 패치)에서 오탐 위험이 있습니다. 또 즉시 크래시가 아니므로 경고로 둡니다.
