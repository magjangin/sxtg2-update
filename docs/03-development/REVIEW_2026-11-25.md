# 코드 점검 2026-11-25 (v2.3.6)

3차 전 파일 감사. 앞선 감사(2026-11-24, v2.3.5)가 오프라인 대조·파서·미디어 쪽을 많이 다뤘으므로, 이번에는 **업데이트로 패치가 일부만 붙었을 때 게임이 어떻게 되는가**와 **플레이 중 매 프레임·매 노트 경로의 IL2CPP 비용**을 다시 봤습니다.

## 1. 업데이트 내성: 커스텀 곡 경로가 반쪽이면 CUSTOM 탭을 만들지 않음

**문제.** 게임 업데이트로 커스텀 곡 플레이에 필요한 패치 중 하나만 빠져도(사전 JIT 검사·시그니처 대조·ICF 보호·대상 못 찾음) CUSTOM 탭은 그대로 생겼습니다. 탭 추가 패치(`CategorySelectController.LoadData`, `GetSelectableCategoty`)는 따로 붙기 때문입니다. 그 상태에서 곡을 고르면:

| 빠진 패치 | 결과 |
| --- | --- |
| `SixtarGlobal_GotoPlayScene_Patch` | 커스텀 상태가 켜지지 않아 공식 곡처럼 로딩 → FMOD 뱅크 조회 NRE로 로딩 화면에서 멈춤 |
| `SixtarGlobal_GotoPlayScene_LoadBundle_Patch` | 같은 NRE로 로딩 화면에서 멈춤 |
| `MikazukiConverter_Parse_Patch` | 게임 해석기가 BMS 텍스트를 Mikazuki 형식으로 읽다 실패 |
| `TrackSelectController_GetTracks_Patch` | 공식 필터가 CUSTOM 카테고리를 처리(빈 목록 또는 예상 밖 동작) |
| `PlayAssist.PlayRecordModule_RecordPlayData_Patch` | `CUSTOM_…` 곡 ID 기록이 로컬 기록 파일에 저장됨 |

`업데이트 점검 결과` 줄에 "필수 빠짐"이 뜨긴 했지만, 로그를 보지 않는 사용자는 곡을 고른 뒤 게임을 강제 종료해야 했습니다.

**수정.**
- `PatchResilience`가 실제로 붙은 패치 클래스를 기억(`AppliedPatches`)하고 `IsApplied(Type)`·`MissingOf(params Type[])`를 제공.
- `Core.CustomPlayReady`: 위 5개 패치가 모두 붙었을 때만 true. 아니면 `[CustomCategory] 커스텀 곡 플레이에 필요한 패치가 빠져 CUSTOM 탭을 만들지 않음 …: <빠진 패치 이름>` 오류를 한 번 남기고, 두 카테고리 Postfix가 CUSTOM을 넣지 않음. 공식 곡은 그대로 플레이 가능.
- 패치 적용 직후 한 번 평가해 결과가 부팅 로그의 패치 요약 바로 아래에 나옴(정상이면 `커스텀 곡 플레이 경로 패치 모두 적용됨, CUSTOM 탭 사용 가능`).
- 게이트 목록의 패치는 모두 `[CriticalPatch]`여야 함을 `SourceHygieneTests.CustomPlayGatePatchesAreCritical`로 고정(아니면 빠져도 "필수 패치 빠짐" 없이 탭만 조용히 사라짐).

## 2. 병목: 노트 위치 훅의 노트·프레임당 래퍼 할당

`NoteEffects`의 `NoteObject.set_HeadPosition`/`set_NoteLength` Prefix(속도 카오스·히든·페이드를 켠 플레이에서만 동적으로 붙음)는 **보이는 노트마다 매 프레임 두 번** 불립니다.

| 전 | 후 |
| --- | --- |
| 노트별 속도 카오스: `note._tickData`(인터롭 필드 읽기)가 호출마다 `il2cpp_field_get_offset` + 새 `SixtarTick` 래퍼(GC 핸들 할당 + 종료자) | 오프셋을 처음 한 번 `il2cpp_field_get_offset`으로 구해(`LambdaTranslator.GetIl2CppFieldOffset`, 덤프 `0x30`과 일치) `Marshal.ReadIntPtr`로 포인터만 읽음. 오프셋을 못 구하면 경고 한 번 후 예전 경로 |
| `note.Pointer`(GC 핸들 조회 네이티브 호출)를 한 호출에서 최대 4번 | 한 번 읽어 `Factor`·`ApplyLaneCover`에 넘김 |

`RandomNoteSkin.OnNoteSpawned`/`EnsureCatalog`도 스폰마다 렌더러·노트 `Pointer`를 두 번씩 읽던 것을 한 번으로 줄였습니다.

## 3. 병목: 장면 페이드 중 볼륨 재적용

`SceneLoader`의 페이드는 `SoundModuleForFMOD.set_CurrectionVolume`을 매 프레임 부르고, 그 Postfix(`ApplyVolumes`)는 커스텀 스트림이 없어도 보정 볼륨 getter(IL2CPP 속성 호출)를 불렀습니다. 공식 곡·메뉴 전환마다 페이드 프레임 수만큼 낭비 → 스트림이 없으면 바로 반환.

## 4. 보고 그대로 둔 것

- `PlayAssist.EnsureSession`의 `jp.Pointer`(판정·틱·입력마다): 세션 경계 판정에 꼭 필요하고 호출당 한 번이라 유지.
- `MediaOverrideManager.KeyOf`의 문자열 할당(커스텀 자켓 행 스크롤마다): 커스텀 곡 행에서만 생기고 작아서 유지.
- `Core.OnLateUpdate`의 예외 처리: 같은 오류가 매 프레임 반복될 수 있으나 첫 오류만 기록하고, 반복 예외 비용은 측정상 문제되지 않아 유지.
