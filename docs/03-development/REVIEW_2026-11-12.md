# 코드 리뷰·람다 찾기 강화 기록 (2026-11-12)

직전 리뷰는 [REVIEW_2026-11-10.md](REVIEW_2026-11-10.md). 이번 범위는 업데이트 내성 계층(`Managers/LambdaTranslator.cs`,
`PatchResilience.cs`, `IcfScanner.cs`, `UpdateGuard.cs`)과 그것을 쓰는 패치 9개(`Core.cs`, `Features/AttendancePopup.cs`)입니다.
검증 빌드: Steam `26455233`, MelonLoader 0.7.3.

## 2. 조치

### 람다 찾기 (`LambdaTranslator.cs`, 새 `NativeLambdaScan.cs`)

- **후보**: 클로저 + 바깥 형식 자신의 인스턴스 메서드. 람다 번호(`b__N` / `b__M_N`의 N, Roslyn의 메서드 안 람다 순번 = 소스 순서)로 정렬.
- **거르기**: ① `requiredClosureMembers`(패치가 읽는 캡처 필드, 예: `track`, `args`)가 있는 클로저만, ② 콜백이면 소유자(`TOwner`)에 닿는
  람다만(정적 `<>c` 제외, 바깥 형식 인스턴스 메서드는 `__instance`가 곧 소유자), ③ 파라미터 형식이 정확히 같은 것 우선.
  거른 결과가 0개면 거르지 않고 경고.
- **기계어 대조** (`NativeLambdaScan`, IL2CPP 의존 없는 순수 함수):
  - 엄격 모드: 레지스터를 따라감. 진입 시 rcx = 클로저(바깥 형식 메서드면 소유자), `mov r, [클로저 + <>4__this]` → r = 소유자,
    `mov r2, r` 복사도 따라감, 덮어쓰면 해제. 대상 필드 로드의 **기준 레지스터가 소유자일 때만** 맞음. 명령 길이(ModRM/SIB/변위)만큼 건너뛰고,
    `CC CC`(함수 끝 패딩)에서 멈춤. 스캔 192바이트.
  - 모든 후보를 대조해 맞는 개수를 셈: 1개 → `how=native`, 0개면 느슨 모드(예전 방식)로 다시 → 1개면 `native-loose`,
    2개 이상 → `ambiguous`(경고), 0개 → `order`(경고). 후보가 하나여도 대조해, 소유자는 읽는데 대상 필드를 안 읽으면 경고.
- **캐시**: 항목에 `how`·`candidates` 저장. 직행 때 현재 네이티브 주소가 저장된 RVA와 다르면 재번역. `order`/`ambiguous`로 고른
  항목은 매 부팅 경고. 항목마다 필드를 따로 읽어 옛 형식도 읽힘. 읽기 실패 시 빈 사전. 이번 실행에서 아무 패치도 묻지 않은 키는 정리.
  임시 파일에 쓰고 바꿔치기.
- **코루틴**: 이름이 정확히 `접두사 + 숫자`인 상태머신만, 여러 개면 번호가 가장 작은 것 + 경고. 상태 필드 없으면 경고.
- 콜백에서 소유자 접근자를 못 만들면 경고.

### 패치·적용부

- `GotoPlayScene` 번들 콜백: `FindClosureMethodCapturing(…, new[] { "track", "args" }, …)`, `[CriticalPatch]` 추가. 대상은 찾았는데
  `track` 접근자나 패턴 콜백이 없으면 `TargetMethod`가 null → 패치 실패 + `[Harmony] 필수 패치 빠짐`으로 드러남.
- `TrackObject` 목록 자켓 콜백: `requiredClosureMembers: { "track" }`.
- `FindMethodInType`: 정확한 형식 우선, 여러 개면 번호 순 첫 번째 + 경고.
- `ApplyAllPatches`: 대상을 미리 못 구했는데 붙은 패치는 `[Harmony/ICFGuard] … ICF 검사 없이 적용됨` 경고.
- `IcfScanner`: 공유 이름 3개까지.

## 3. 검증

**오프라인** (`tools/lambdascan`, 모드의 `NativeLambdaScan.cs`를 그대로 컴파일해 실제 `GameAssembly.dll` 바이트로 실행): 35건 통과.
자켓 람다 4개(`PlayLoading b__2/b__4`, `Result b__3/b__4`)는 자기 필드에만 Hit, 짝 필드에는 OwnerOnly. `TravelBackground b__1`(바이트 저장
`mov byte [rax+0x58],1`은 무시), BGA `b__2`(`mov rbx, rcx` 경유), `TrackObject b__1`(소유자 0x10, 0x18은 `track` — 엄격 모드는 0x18을 소유자로
오인하지 않음), 합성 바이트(바깥 형식 메서드, REX.B+SIB, 소유자 레지스터 덮어쓰기). 처음에 "BGA `b__2`는 `jacket`(0x20)을 안 읽는다"고 기대값을
적었다가 실패 → 디스어셈블해 보니 clip이 null일 때 0x654CEA에서 `jacket`을 실제로 읽음(기대값이 틀렸음).

## 4. 이번에 안 한 것

- **커스텀 곡 플레이는 이번에도 실기로 돌리지 않았습니다.** 바뀐 플레이 경로는 `GotoPlayScene` 번들 콜백의 대상 찾기뿐이고, 3회차에서 같은 람다(`0x7EB2E0`)와
  접근자가 잡혔습니다(접근자가 없으면 오류 로그가 남는데 없었음). 다음에 게임을 켤 때 커스텀 곡 1곡을 결과 화면까지 플레이해 보세요.
- 업데이트로 람다가 실제로 바깥 형식으로 옮겨 간 사례는 이 빌드에 없어, 그 경로(`getOwner = __instance`)는 합성 바이트 스캔까지만 시험했습니다.
