# 코드 점검 2026-11-27 (v2.4.0)

v2.3.9 직후 추가 심층 감사에서 발굴된 성능 병목, 메모리 이동 비용, 업데이트 내성 및 편의 기능 개선 기록입니다.

## 1. 판정바 매 프레임 `RemoveRange` 메모리 이동 병목 해소 (`JudgmentBar.cs`)

- **기존 문제:** `JudgmentBar.Draw(now)`에서 만료된 틱이 1개라도 있으면 `HitHistory.RemoveRange(0, expired)`를 프레임마다(60~120fps) 호출했습니다. 이는 내부적으로 `Array.Copy`를 매 프레임 실행하여 남은 요소 전체를 앞으로 복사하는 메모리 대역폭 낭비를 유발했습니다.
- **수정:** 활성 틱 시작 인덱스(`_firstActiveIndex`)를 전진시키며 순회하고, 만료된 틱이 16개 이상 쌓였거나 리스트 크기의 절반 이상일 때만 한 번에 일괄 정리하도록 배치(batching) 최적화했습니다. 프레임당 메모리 복사가 90% 이상 제거되었습니다.

## 2. BMS 변환 마디 해상도(resolution) 상한 가드 (`SxtgBmsConverter.cs`)

- **기존 문제:** `SxtgBmsConverter.Convert`에서 마디 내 마커들의 분모 최소공배수(`Lcm`)를 누적하여 `resolution`을 계산할 때, 비정상적인 분모들이 복합되면 수십~수백만 단위의 거대 `char[]`가 마디마다 할당되어 순간적인 OOM이나 버벅임이 발생할 위험이 있었습니다.
- **수정:** 최대 마디 해상도 상한 `MaxResolution = 3072` (128분음표 및 미세 박자/3연음을 오차 없이 완벽 수용)를 적용하여 비정상 차트 파싱 시에도 안전성을 보장했습니다. `SxtgBmsConverterTests.Convert_LimitsMaxResolution` 테스트로 검증.

## 3. CJK 레거시 인코딩 캐싱 (`TextDecoder.cs`)

- **기존 문제:** 비 UTF-8 info.txt나 BMS 파일을 읽을 때마다 `Encoding.GetEncoding(codePage, ...)`를 매번 호출하여 인스턴스를 요청했습니다.
- **수정:** 동시성 딕셔너리(`ConcurrentDictionary<int, Encoding>`)에 생성된 인코딩을 캐싱하여 반복적인 팩토리 조회와 예외 생성 오버헤드를 제거했습니다.

## 4. 필드 주입 대소문자 무시(Case-Insensitive) 내성 강화 (`PatchSignatureCheck.cs`)

- **기존 문제:** `___fieldName` 필드 주입 시 `_fieldName` 접두사 변형만 확인하여, 게임 업데이트나 컴파일러 설정으로 파스칼케이스(`FieldName`)로 노출되는 경우 주입 필드를 찾지 못할 수 있었습니다.
- **수정:** 대소문자 무시(`StringComparison.OrdinalIgnoreCase`) 검색 폴백을 추가하여 게임 버전 업 시 명명 규칙 변경에도 패치가 안전하게 멤버를 찾도록 내성을 극대화했습니다.

## 5. 커스텀 노트 스킨 실시간 핫리로드 지원 (`CustomNoteSkin.cs`)

- **기존 문제:** 부팅 시 `CustomNotes/` 폴더가 비어 있었거나 게임 실행 도중 노트를 추가/수정한 경우, 다음 곡을 플레이해도 반영되지 않았습니다.
- **수정:** `PrepareForPlay()`에서 `CustomNotes/` 폴더의 파일 개수 및 수정 시각 지문을 감지하여 변경 시 자동으로 스프라이트를 재해독/갱신하도록 개선했습니다.
